# Environments and the Toy Evaluator

We used this input: `(let ((n 1)) (let ((f (lambda (x) (+ x n)))) (let ((n 100)) (f 2))))`. The outer `(let ((n 1)) ...)` enters the `let` branch of `eval-expr`, which calls the function `eval-let`. It evaluates the init `1` and binds `n`, creating the env `((n . 1))`. In the body, the next `let` evaluates `lambda (x) (+ x n))`, and `make-closure` returns the closure that saves ((n . 1)), and this closure is bounded to `f`. This function is responsible for capturing the defining `env`. As soon as the `lambda` is finished being evaluated, it takes the `env` `eval-expr` currently has and stores it as `(list :closure params body env)`, which can then be read later using apply-closure.

Next, the innermost `let` then binds `n = 100`, following the same branch as the outer `let` above. So, `let` binds `n = 100` and the env becomes `((n . 100) (f . (:closure (x) (+ x n) ((n . 1))) (n . 1)`. Next, `(f 2)` looks up `f` to get the closure, evaluates `2`, and `apply-closure` adds `x = 2` to the closure's env, resulting in `((x . 2) ( n . 1))`. The body `(+ x n)` then evaluates it, which results in `3`.

If application joined the arguments to the caller's environment instead, the `apply-closure` would use the environment live at the call site, `((x . 100) ...)`, instead of the saved one, `((n . 1))`. This is dynamic scoping, and the same form would return `2 + 100 = 102` instead of `3`. A closure returned out of its defining scope, such as `(let ((make-adder (lambda (n) (lambda (m) (+ n m))))) ((make-adder 1) 2))`, would fail with "Unbound variable: n" because `n` does not exit in the caller's environment.

As for why the host CLISP needs `funcall` while toy language doesn't depend on how each language manages namespaces, the host CLISP is a Lisp-2, while toy language is a Lisp-1. In CLISP, when the operator position of a form is a symbol, it is looked up in the function namespace, so a function held in a variable, such as a parameter, can't be called as `(f x). funcall` bridges the gap by evaluating its first argument as a normal variable and then applying the result, and `#' (function)` goes the other way, getting a named function into a variable. This is why the host code writes `(mapcar #' cons ...)` and `(funcall f x)`. In the toy language, variables and functions share one namespace, and `eval-expr` evaluates the operator position like any other expression, line 142, so a variable holding a closure can be called as `(f 2)`. That removes the need for `funcall`, `#`, and a second environment, which keeps the parser and evaluator small.
